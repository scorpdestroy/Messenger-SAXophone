## Локальная проверка

- Docker Compose: PostgreSQL, backend и frontend healthy; миграция применяется автоматически.
- Backend: 4 теста прошли в контейнере с PostgreSQL; health/404/readiness и ограничения БД.
- Alembic: upgrade → check → downgrade → upgrade → check на отдельной одноразовой БД прошли.
- Frontend: lint, 2 unit-теста и production build прошли.
- Playwright: 2 сценария на 375/1440 px, каждый открывает 6 маршрутов; проверены Vite и собранный Nginx.
- HTTP smoke: прямой backend и /api/ready через Nginx прошли.
- npm audit после обновления Vitest: 0 известных уязвимостей.
- Скриншоты desktop/mobile визуально проверены; локально в .local, в Git не включены.

CI подготовлен, но запуск именно GitHub Actions ещё не выполнен: код приложения ещё не отправлен; правила и макеты опубликованы отдельно.
В TestClient есть предупреждение о будущем переходе upstream с httpx на httpx2;
на текущей зафиксированной версии все тесты проходят. В контейнере pytest может предупредить
о недоступном кэше тестов; это не влияет на проверки.

## Коммиты и дальнейшие действия

Девять последовательных patches экспортированы в `.local/prepared-commits`.
Сообщения и списки файлов находятся в `commit-plan.json`; экспорт не меняет реальный Git index
и не назначает автора. Основание очереди: опубликованная docs/S1-10-git-workflow с правилами руководителя.
Опубликованный develop указывает на исходный main; release создаётся после интеграции и регресса.

Для настоящего авторства нужны имя, GitHub login, подтверждённый email/noreply и реальный вклад.
Необходимы реальные review и подтверждение распределения PO/SM. До этого карточки
не должны автоматически переходить в Done. Полноценные auth и личные диалоги — следующая работа S2/S3.


Правила опубликованы коммитом b33ef7f от scorpdestroy; макеты — d35edc3 от AleksanderTep.
Доступ команды и принятие PR требуют отдельной проверки. Из очереди исключены уже
опубликованные правила, шаблон PR и таблица участников. UI-компоненты выделены в отдельную
группу перед оболочкой, которая их импортирует. Сведения о публикации очереди сохраняются локально.
